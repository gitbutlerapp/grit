# grit

`grit` is a small, opinionated Git client. It reads and writes ordinary Git repositories, so `git` and `grit` can be used on the same repository. It does not mirror Git's commands or flags: there is usually one obvious way to do each thing, and every command can answer in JSON.

This skill was generated by `grit {version}`. Run `grit <command> --help` for the exact options of the installed version.

## Rules

- Pass `--json` whenever you will read the result. stdout then holds exactly one JSON object; progress and prompts go to stderr.
- Use `--filter '<jq-like expr>'` (with `--json`) to keep only what you need: `grit status --json --filter '{branch, clean}'`.
- On failure the exit code is usually 1 and stdout is `{"error": "…"}` (or a structured object with `kind`). Exit code 2 is usage (unknown flag, bad `--hunks` ids, …); with `--json`, stdout still has `{"error": "…"}`. See `content/docs/exit-codes.md` for 128/129 and command-specific checks.
- Always give `grit commit` a message (`-m`, a positional argument, or `-F` / `--message-file`, with `-` for stdin). It never opens an editor. Use `--author "Name <email>"` to override the author once; `--no-verify` skips `pre-commit` and `commit-msg`. Use `--dry-run` to preview paths, parents, and author without writing objects or updating refs (`--json` omits `oid` and sets `dry_run: true`).
- Don't translate Git habits flag-for-flag. `grit commit -a` and `git add -p` don't exist here; use `grit commit --amend` to replace the tip commit and `grit rebase` for replay onto another base (see "What grit doesn't do" for the rest). Use `grit reset` (`--soft`, `--mixed`, `--hard`, `--keep`, `--dry-run`) instead of `git reset`.

## New repositories

`grit init` creates an empty repository. Default branch is `main`, or `init.defaultBranch` from your Git config when you omit `-b`. Use `-b develop` / `--initial-branch` to override. `--object-format sha256` creates a SHA-256 object database; `--separate-git-dir <path>` keeps `.git` as a gitfile pointing at an external directory. Reinit keeps the existing `HEAD` branch (a new `-b` name is ignored). `--json` includes `branch`, `object_format`, and `git_dir` when separate.

## Where am I?

```console
$ grit status --json
```

Plain `grit` is the same as `grit status`. Keys: `branch`, `detached`, `head`, `target` (the branch your work is headed for), `ahead`, `commits` (up to ten not on the target; each commit row includes `change_id` and `change_id_stored`), `staged`, `unstaged`, `untracked`, `clean`.

The target branch is the first that exists of: the `target.branch` config value, `origin/master`, `origin/main`, `master`, `main`. Change it with `grit config target.branch origin/develop`.

## Reading history and changes

| Task | Command |
| --- | --- |
| Uncommitted changes as a diff | `grit diff` |
| Changed paths only | `grit diff --name-only` |
| Per-file line counts | `grit diff --stat` or `grit diff --numstat` |
| The change one commit made | `grit show <commit>` (patch by default; merge commits use combined diffs unless `--diff-merges=first-parent`) |
| Several commits at once | `grit show <A> <B>` (`--json` → `{ "objects": [ … ] }`) |
| Blob or tree at a revision | `grit show <rev>:<path>` (same resolution as `grit cat`) |
| A commit's message and diffstat only | `grit show [<commit-or-branch-or-tag>] --stat` |
| Recent history, ten at a time | `grit log`, then `grit log --before <next>` using the `next` value |
| History with patches or file lists | `grit log -p`, `grit log --stat`, `grit log --name-status`, … (same format flags as `grit diff`) |
| Commits on this branch not on the target | `grit shortlog` or `grit ahead`; add `--target <REF>` to pick the base |
| Skip formatting commits in blame | `grit blame --ignore-rev <OID>` or `grit blame --ignore-revs-file .git-blame-ignore-revs` (set `blame.ignoreRevsFile` in config for a default list) |
| What happened to this branch recently | `grit reflog [REF] --json` (`old_oid`, `new_oid`, `date`, `committer`, plus `oid` / `relative_date`) |

`grit diff --json` on **`--staged`** or **`--unstaged`** patch output includes stable **`hunks[].id`** (12 lowercase hex chars) and **`hunks[].index`** (0-based within the file). Ids hash side, path, and line bodies (not line numbers), so they stay valid when earlier hunks are staged. Use **`grit add --hunks <id,...>`** or **`grit add --lines path:start-end`** (new-side **`lines[].new`**, 1-based inclusive); commit-range diffs omit `id` for now.

**Partial staging:** `grit diff --unstaged --json -- path | jq '.files[].hunks[] | .id'` → `grit add --hunks id1,id2 -- path`, or pick **`lines[].new`** → `grit add --lines path:10-15 -- path`. Mix `--hunks` and `--lines`. One-shot commit: **`grit commit --hunks id1,id2 -m msg -- path`** or **`grit commit --lines path:10-15 -m msg -- path`**. Shelve selected unstaged hunks without touching the index: **`grit stash push --hunks id1,id2`** (optional **`--dry-run`**). Shelve only some paths (others stay dirty): **`grit stash push -- path1 path2`**. Restore the stashed index on apply/pop: **`grit stash apply --index`**. Use `--dry-run` to preview partial hunks. Exit code **2** for unknown/stale ids or invalid line ranges.

**Partial discard / unstage:** same ids or line ranges on **`grit restore --hunks`** / **`grit restore --lines`** (default: worktree; add **`--staged`** to unstage selected hunks). **`--dry-run`** previews without writing.

Revisions can be full or short ids, branch or tag names, or expressions like `HEAD~2`.

Commit rows in `--json` from `log`, `show`, `revs`, and `status` share `change_id` (reverse-hex) and `change_id_stored`. Human `log` and `show` prefix each commit with `change <8 chars>`; `--oneline` does not.

## Committing

```console
$ grit commit -m "Explain what changed and why"
```

`grit commit` **auto-stages** the whole worktree by default (`commit.autoStage=true`). Use **`grit commit --staged`** to commit only the index (set `commit.autoStage=false` to make that the default). Use **`grit commit -m msg -- <paths>`** (or `--pathspec-from-file`) for a partial commit that leaves other staged changes alone — like `git commit --only`. `-a` / `--all` forces auto-stage; `--staged` and paths cannot be combined with each other or with `-a`.

**Partial hunks:** `grit diff --unstaged --json` → pick `hunks[].id` → **`grit commit --hunks id1,id2 -m msg`** (optional `-- paths`). Same exit code **2** as `grit add --hunks` for unknown or stale ids. **`grit commit --patch-file file`** applies a cached patch then commits. Neither mode auto-stages the rest of the tree.

### Staging (`grit add`)

| Task | Command |
| --- | --- |
| Stage everything (modified, deleted, untracked) | `grit add` |
| Stage only tracked edits and deletions | `grit add -u` (or `grit add --update`) |
| Preview without writing the index | `grit add --dry-run` (combine with `-u` or paths) |
| Record intent to add (empty index slot, no blob yet) | `grit add -N -- path` (requires paths; does not alter tracked entries) |
| Stage an ignored path | `grit add -f -- ignored.log` |
| Stage specific paths | `grit add -- path/to/file` |
| Apply a unified diff to the index | `grit add --patch-file file.diff` (or `-` for stdin; like `git apply --cached`) |
| Stage selected diff hunks by id | `grit add --hunks <id,...>` (from `grit diff --json`; optional `-- paths`) |
| Stage part of a hunk by line range | `grit add --lines path:start-end` (new-side lines from `grit diff --json`; mix with `--hunks`) |

`grit add --json` returns `{added, modified, removed, intent_to_add, dry_run, count, staged}` with repository-relative paths. Use `--dry-run` before bulk staging to bound agent work; path lists are sorted and stable. With `--patch-file`, paths come from the patch (same JSON fields as path-based staging).

### Removing, renaming, and cleaning paths

| Task | Command |
| --- | --- |
| Stop tracking (and delete from disk by default) | `grit rm -- <paths>` |
| Preview `rm` without writing | `grit rm --dry-run -- <paths>` |
| Ignore missing pathspecs on `rm` | `grit rm --ignore-unmatch -- <paths>` |
| Rename or move tracked paths | `grit mv <source>... <destination>` |
| Preview `mv` | `grit mv --dry-run <source>... <destination>` (`--json` → `{moves:[{from,to}], dry_run}`) |
| List untracked paths to delete | `grit clean` (dry run by default) |
| Delete untracked paths | `grit clean -f` |
| Remove only ignored untracked files | `grit clean --only-ignored` (not combinable with `--ignored`) |
| Exclude paths from clean | `grit clean -e '<pattern>'` (repeatable) |
| Clean files but not directories | `grit clean --files-only` |

`grit commit` fails with "nothing to commit" on a clean tree unless you pass `--allow-empty`. On detached HEAD it advances `HEAD` without moving a branch; use `grit switch -c <name>` to keep the commits on a new branch.

Each commit gets a stable **`change-id`** header (on by default) that survives `--amend`. Disable with `grit config grit.changeIds false` when you need Git-identical commit objects. See the docs site section on change ids for derivation and testing config.

## Branches

| Task | Command |
| --- | --- |
| List branches | `grit branch` |
| List with filters / JSON detail | `grit branch --list 'feat*' -a --merged main --sort date -n 20 --json` |
| Current branch name only | `grit branch --show-current` |
| Create a branch at the current commit (no switch) | `grit branch <name>` |
| Create at a specific commit | `grit branch <name> <start>` |
| Create with upstream tracking | `grit branch -t <name> <remote>/<branch>` or rely on `branch.autoSetupMerge` |
| Rename a branch | `grit branch -m [<old>] <new>` or `grit branch -M <new>` (force) |
| Set / clear upstream | `grit branch -u <upstream> [<name>]`, `grit branch --unset-upstream [<name>]` |
| Preview any branch mutation | add `--dry-run --json` (no ref, config, or reflog changes) |
| Create and switch | `grit switch -c <name>` |
| Switch | `grit switch <name>` (also `grit checkout`, `grit co`) |
| Delete a merged branch | `grit branch -d <name>` |
| Delete regardless of merge | `grit branch --force-delete <name>` (short `-D`) |
| Predict merge conflicts (no repo changes) | `grit merge --check <branch>` (exit 0 = clean/ff/up to date, 1 = would conflict; `--json` → `result: clean\|conflicts\|…`) |

`grit branch --json` and `--markdown` list with `full_ref`, `oid`, `subject`, `date`, optional `upstream` (`ref`, `remote`, `gone`, `ahead`, `behind`), and `worktree` when checked out elsewhere. Human list output adds an upstream marker when configured.

`grit switch`, `grit merge`, `grit pick`, `grit revert` and `grit pull` refuse to run when checkout would overwrite local edits or untracked files. Preflight with `grit switch <branch> --dry-run --json` (checks only; reports `changed_paths`) before switching. On refusal, `--json` emits `kind: would_overwrite` with `reason` (`local_changes` or `untracked`) and sorted `paths`.

## Combining work

- `grit merge <branch>` fast-forwards when it can, otherwise records a merge commit. `<branch>` can be local or remote-tracking (`origin/main`). Use `grit merge --check <branch>` to predict conflicts in memory without touching refs, the index, or the worktree. Common flags: `--ff-only` (exit 128 when diverged), `--no-ff`, `--squash` (writes `SQUASH_MSG`; finish with `grit commit`), `--no-commit` (Git merge state; finish with `grit commit`), `-X ours|theirs`, `--conflict diff3|zdiff3|merge`, `--allow-unrelated-histories`, `-m` / `--message-file`.
- `grit pick [<commit>…]` cherry-picks commits onto the current branch (ranges OK). Use `grit pick --check` to predict conflicts without changing refs, the index, or the worktree (exit 0 = clean, 1 = would conflict or empty stop). `-X ours|theirs` auto-resolves replay conflicts; `--conflict diff3|zdiff3|merge` sets marker style when a step stops.
- `grit revert [<commit>…]` undoes one or more commits (ranges OK; newest first). Merge commits need `--mainline <n>`. `-m` / `--message-file` set the message for a **single** commit only. `grit revert --check` matches pick’s `--check` contract; same `-X` and `--conflict` flags apply.
- `grit revert --continue`, `--abort`, and `--skip` resume or cancel a stopped revert sequence (same conflict model as pick).
- On a conflict these commands update the index and working tree with conflict markers, exit 1, and leave merge/pick/revert/rebase state on disk. To inspect a side or recreate markers without resolving, use `grit restore --ours`, `--theirs`, or `--merge` on the conflicted paths (index stays unmerged). Fix conflicts (`grit diff`), stage (`grit add`), then finish with `grit commit` for merges or `grit pick --continue` / `grit revert --continue` / `grit rebase --continue`. Use `--abort` on the same command to cancel; `grit rebase --skip` skips the current commit.

## History rewrites

- `grit history drop`, `move`, `reword`, `fixup`, `squash`, and `absorb` share `--dry-run`, `--update-refs`, `--empty=(drop|keep|abort)` (empty replayed commits), and `--keep-committer` (preserve each replayed commit’s committer line).
- `grit history fixup` accepts **`--hunks`** and **`--lines`** like `grit add` to fold selected unstaged edits into a historical commit without staging the whole file; optional `-- paths` narrows the diff. Without those flags, fixup uses the staged index (same as before).

## Remotes

| Task | Command |
| --- | --- |
| Copy a repository | `grit clone <url> [<dir>]` (`--depth N`, `-b` / `--branch` for a branch or tag; hidden `--shallow` = `--depth 1`) |
| List, add, remove, or show remotes | `grit remote`, `grit remote add <name> <url>`, `grit remote -v`, `grit remote remove <name>` (`--dry-run`), `grit remote show <name> [--no-query] [-n N]` |
| Fix a remote URL | `grit remote set-url <name> <url>` (fetch URL); `grit remote set-url --push <name> <url>` for push only; `--dry-run` to preview |
| Download without changing your branch | `grit fetch [<remote>]` |
| Fetch one branch or ref | `grit fetch origin main` (or `grit fetch origin pull/123/head:pr-123` for a PR) |
| Shallow fetch controls | `grit fetch --depth N`, `--deepen N`, or `--unshallow` (same semantics as Git; mutually exclusive) |
| Fetch and merge the remote copy of this branch | `grit pull` |
| Pull only when a fast-forward is possible | `grit pull --ff-only` (exit **0** on success, **1** with `refused_not_ff` when diverged; branch unchanged) |
| Fetch and replay local commits on top of upstream | `grit pull --rebase` (or `pull.rebase` in config; rebase conflicts abort atomically, exit **1**) |
| Replay local commits onto another base | `grit rebase [<upstream>]` (default `@{upstream}`; `--onto`; `--check` predicts conflicts without side effects; `-X ours\|theirs` matches `git rebase -X` where **ours** is onto/upstream; stop on conflicts with `--continue` / `--abort` / `--skip`, exit **1**) |
| Publish this branch to `origin` under the same name | `grit push` |
| Push to a different remote branch name | `grit push origin HEAD:refs/heads/<name>` |
| Publish rewritten history safely | `grit fetch`, then `grit push --force-with-lease` (or `--force-with-lease=<rev>` for one ref); stale lease → exit **1**, `"rejected": true` |
| Publish all local tags | `grit push --tags` |

Ordinary pushes must fast-forward the remote. If the remote has commits you don't, grit rejects the push (exit **1**, `"rejected": true`); run `grit pull`, then push again. After `grit history` edits (reword, drop, fixup, squash, split, rebase) or `grit rebase`, fetch and use `--force-with-lease` instead of `--force` so you don't overwrite someone else's work. `--force` overwrites unconditionally when you really need it.

After a successful history rewrite (drop, move, reword, fixup, squash, absorb, or rebase apply), grit stores the ref plan in `.git/grit/history-last`. `grit history undo` restores those refs when tips are unchanged; run it again to redo. Use `--dry-run` to preview ref movements. Undo refuses when a ref moved or local changes would be overwritten.

URLs can be `https://`, `ssh://`, `user@host:path`, `git://`, `file://` or a local path.

## Tags and config

- `grit tag` lists tags (default `--sort=version`). Filters: `-l/--list <pattern>` (repeatable), `--sort version|date|name`, `--reverse`, `--contains [REV]`, `--points-at <REV>`, `-n` / `--limit`. List `--json` includes `target_kind` and `annotation` (subject, message, tagger, date) on annotated tags; human output shows the subject beside the name.
- `grit tag <name> [<target>]` creates a lightweight tag at `HEAD` or `<target>`. `-m` / `-F` create an annotated tag; `-f` replaces an existing tag; `--dry-run` previews create/delete. `grit tag -d <name>` deletes one. `grit tag --verify <name>…` checks annotated tag signatures and optional `tree-sha256` claims (exit 1 if any fail); `--no-signature` skips signature checks.
- `grit config <key>` reads, `grit config <key> <value>` sets, `grit config --unset <key>` removes, `grit config --list [<prefix>]` lists. Scope with `--global`, `--local`, `--system`, `--worktree`, or `-f <path>`. Multi-value: `--add`, `--all`, `--unset-all`. Typed values: `--type bool|int|path`, `--default` on read. Sections: `--rename-section OLD` + `--rename-section-new NEW`, `--remove-section NAME`. Every write accepts `--dry-run`. Missing keys exit **1**; `--json` returns `"value": null` with scope/file/line when set.

## Staying non-interactive

- HTTPS GitHub: run `grit auth` once in an interactive session (it uses a browser device flow). After that, fetch, pull and push use the stored token. When stdin isn't a terminal, grit won't prompt to sign in; it fails with a hint instead.
- SSH: set `GIT_SSH_COMMAND='ssh -o BatchMode=yes'` so a missing key or unknown host fails fast instead of waiting for input.
- Don't run `grit update` in automation; it reinstalls the binary.
- `grit manager`, `grit upload-pack` and `grit receive-pack` are plumbing that speaks Git protocols on stdin/stdout. Don't call them directly.

## What grit doesn't do

grit has no equivalent of interactive commands or annotated or signed tags. Use `grit reset` and `grit rebase` / `grit history` instead of Git's reset and interactive rebase. Partial staging and discard use `--hunks`, `--lines`, and `--patch-file` on `add`, `restore`, `commit`, and `stash push`, not Git's `-p` / `-i`. During a merge conflict, use `grit restore --ours|--theirs|--merge` to compare sides or restore markers, then `grit merge --continue` (or `grit commit` for Git-compatible finish). Use `grit commit --amend` (optional message, JSON `amended` field) to rewrite the tip commit. For `grit stash pop` or `grit stash apply` with worktree merge conflicts, resolve paths (for example with `grit restore --ours|--theirs|--merge`) and keep or drop the stash entry as needed. Index-only conflicts with `--index` fail without changing the worktree or index. When a task needs something else on this list, use `git` on the same repository and come back to `grit` afterwards.
