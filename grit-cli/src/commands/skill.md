# grit

`grit` is a small, opinionated Git client. It reads and writes ordinary Git repositories, so `git` and `grit` can be used on the same repository. It does not mirror Git's commands or flags: there is usually one obvious way to do each thing, and every command can answer in JSON.

This skill was generated by `grit {version}`. Run `grit <command> --help` for the exact options of the installed version.

## Rules

- Pass `--json` whenever you will read the result. stdout then holds exactly one JSON object; progress and prompts go to stderr.
- Use `--filter '<jq-like expr>'` (with `--json`) to keep only what you need: `grit status --json --filter '{branch, clean}'`.
- On failure the exit code is 1 and stdout is `{"error": "…"}`. Exit code 2 is a usage error (unknown flag or command) and has no JSON.
- Always give `grit commit` a message. It never opens an editor.
- Don't translate Git habits flag-for-flag. `grit commit -a`, `git add -p`, `rebase`, and `reset` don't exist here; use `grit commit --amend` to replace the tip commit (see "What grit doesn't do" for the rest).

## Where am I?

```console
$ grit status --json
```

Plain `grit` is the same as `grit status`. Keys: `branch`, `detached`, `head`, `target` (trunk your work is headed for), `ahead`, `behind` (vs `target`; `null` with `--no-ahead-behind` or `status.aheadBehind=false`), `upstream` (`{ref, ahead, behind}` when tracking differs from `target`, else null), `commits` (up to ten ahead of the target; each row includes `change_id` and `change_id_stored`), `staged`, `unstaged`, `untracked`, `clean`, `stash_count`. Pass `--ignored` to add an `ignored` path list (same set as Git's `!!` porcelain lines).

Limit to paths with `grit status -- <path>…` (same pathspec rules as `grit add`). Untracked listing: `--untracked no|normal|all`. `--short` prints one line per path for humans (two-letter index/worktree codes; `--json` is unchanged). Staged renames in `--json` use `{ "status": "renamed", "path": "new", "old_path": "old" }`; human output shows `old → new`. Rename detection follows `status.renames` / `diff.renames` (on by default; set `status.renames=false` to disable).

The target branch is the first that exists of: the `target.branch` config value, `origin/master`, `origin/main`, `master`, `main`. Change it with `grit config target.branch origin/develop`.

## Reading history and changes

| Task | Command |
| --- | --- |
| Uncommitted changes as a diff | `grit diff` |
| Changed paths only | `grit diff --name-only` |
| Per-file line counts | `grit diff --stat` or `grit diff --numstat` |
| The change one commit made | `grit show <commit>` (patch by default; merge commits use combined diffs unless `--diff-merges=first-parent`) |
| Several commits at once | `grit show <A> <B>` (`--json` → `{ "objects": [ … ] }`) |
| Blob or tree at a revision | `grit show <rev>:<path>` (same resolution as `grit cat`) |
| A commit's message and diffstat only | `grit show [<commit-or-branch-or-tag>] --stat` |
| Recent history, ten at a time | `grit log`, then `grit log --before <next>` using the `next` value |
| History with patches or file lists | `grit log -p`, `grit log --stat`, `grit log --name-status`, … (same format flags as `grit diff`) |
| Commits on this branch not on the target | `grit shortlog` |

Revisions can be full or short object ids, branch or tag names, change ids (reverse-hex `k`–`z`, 4–32 chars — unique prefix or full id), or expressions like `HEAD~2` and `\<cid\>~1`.

Commit rows in `--json` from `log`, `show`, `revs`, and `status` share `change_id` (reverse-hex) and `change_id_stored`. Human `log` and `show` prefix each commit with `change <8 chars>`; `--oneline` does not.

## Committing

```console
$ grit commit -m "Explain what changed and why"
```

`grit commit` **auto-stages** the whole worktree by default (`commit.autoStage=true`). Use **`grit commit --staged`** to commit only the index (set `commit.autoStage=false` to make that the default). Use **`grit commit -m msg -- <paths>`** (or `--pathspec-from-file`) for a partial commit that leaves other staged changes alone — like `git commit --only`. `-a` / `--all` forces auto-stage; `--staged` and paths cannot be combined with each other or with `-a`.

`grit commit` fails with "nothing to commit" on a clean tree unless you pass `--allow-empty`. It also refuses a detached HEAD.

Each commit gets a stable **`change-id`** header (on by default) that survives `--amend`. Disable with `grit config grit.changeIds false` when you need Git-identical commit objects. See the docs site section on change ids for derivation and testing config.

## Branches

| Task | Command |
| --- | --- |
| List branches | `grit branch` |
| Create a branch at the current commit (no switch) | `grit branch <name>` |
| Create and switch | `grit switch -c <name>` |
| Switch | `grit switch <name>` (also `grit checkout`, `grit co`) |
| Delete a merged branch | `grit branch -d <name>` |
| Delete regardless | `grit branch -D <name>` |

`grit switch`, `grit merge`, `grit pick`, `grit revert` and `grit pull` refuse to run with uncommitted changes. Commit first. They also refuse rather than overwrite an untracked file.

## Combining work

- `grit merge <branch>` fast-forwards when it can, otherwise records a merge commit. `<branch>` can be local or remote-tracking (`origin/main`).
- `grit pick <commit>` applies one non-merge commit to the current branch as a new commit, keeping its author and message.
- `grit revert <commit>` undoes one non-merge commit with a new inverse commit (`Revert "…"` message).
- On a conflict these commands update the index and working tree with conflict markers, exit 1, and leave merge/pick/revert state on disk. Fix conflicts (`grit diff`), stage (`grit add`), then finish with `grit commit` for merges or the matching `--continue` command when pick/revert support lands. Use `--abort` on the same command to cancel.

## Remotes

| Task | Command |
| --- | --- |
| Copy a repository | `grit clone <url> [<dir>]` |
| List or add remotes | `grit remote`, `grit remote add <name> <url>` |
| Download without changing your branch | `grit fetch [<remote>]` |
| Fetch and merge the remote copy of this branch | `grit pull` |
| Publish this branch to `origin` under the same name | `grit push` |
| Publish all local tags | `grit push --tags` |

`grit push` never force-pushes. If the remote has commits you don't, the push is rejected (exit 1, `"rejected": true`); run `grit pull`, then push again.

URLs can be `https://`, `ssh://`, `user@host:path`, `git://`, `file://` or a local path.

## Tags and config

- `grit tag` lists tags, `grit tag <name>` creates a lightweight tag at the current commit, `grit tag -d <name>` deletes one.
- `grit config <key>` reads, `grit config <key> <value>` sets, `grit config --unset <key>` removes, `grit config --list` lists. Add `--global` for the per-user file.

## Staying non-interactive

- HTTPS GitHub: run `grit auth` once in an interactive session (it uses a browser device flow). After that, fetch, pull and push use the stored token. When stdin isn't a terminal, grit won't prompt to sign in; it fails with a hint instead.
- SSH: set `GIT_SSH_COMMAND='ssh -o BatchMode=yes'` so a missing key or unknown host fails fast instead of waiting for input.
- Don't run `grit update` in automation; it reinstalls the binary.
- `grit manager`, `grit upload-pack` and `grit receive-pack` are plumbing that speaks Git protocols on stdin/stdout. Don't call them directly.

## What grit doesn't do

grit has no equivalent of `rebase`, `reset`, partial staging, interactive commands, annotated or signed tags, or conflict resolution. Use `grit commit --amend` (optional message, JSON `amended` field) to rewrite the tip commit. For `grit stash pop` or `grit stash apply` with conflicts, use `git` to finish resolving. When a task needs something else on this list, use `git` on the same repository and come back to `grit` afterwards.
